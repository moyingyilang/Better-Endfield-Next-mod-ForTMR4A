# 导入链性能验收记录（2026-11-27）

目标：参考包导入端到端耗时下降 ≥30%，峰值内存不高于现状，且不损失画质/兼容性。
设备侧实测按用户要求暂不作为门槛；以下为**机制、宿主基准、确定性、正确性**证据。

## 1. 机制改动清单

| 类别 | 改动 |
|---|---|
| 重复 IO | 归档导入走 `openFileDescriptor` + libarchive fd 流式解包（不再整包复制）；BEM 读取改只读 mmap；已压缩 payload 分块流式写 spool；spool→输出缓冲 1 MiB |
| 多余写入 | 转换已安装包时直接从 `bem-installed/<gen>/installed.bem` 读取，不再 staging 复制；导入路径只保留“输入源 + 输出成品”两次必要写 |
| 纹理转码 | 包级 rewrite 只作触发；逐张按设备能力 mask 决定保留/转换；保留纹理**零解码**；ASTC context 按 (profile,block) 复用；纹理间受控并行（≤4 worker、64 MB 解码预算、顺序确定） |
| 几何 payload | raw payload 并行压缩（≤4 worker、64 MB 预算），按提交顺序写 spool；压缩级 9→3（无损） |
| 内存约束 | 两个并行阶段都设 64 MB 解码/原始字节预算，批次大小受控，避免峰值随核数线性上涨 |

## 2. 宿主基准（同一 harness，含纹理转换回调）

| 输入 | 首版基线 | 第 3 轮（mmap/流式） | 第 4 轮（payload 并行） | 相对基线 |
|---|---|---|---|---|
| 26 MB BEM | 1270 ms | 920 ms | **466–485 ms** | **-62%** |
| 73 MB BEM | 2559 ms | 2397 ms | **1306–1311 ms** | **-49%** |

复现：

```bash
scripts/test-rewrite-parallel.sh            # 默认 26 MB 样本
scripts/test-rewrite-parallel.sh <file.bem> # 任意 BEM
```

## 3. 正确性证据

- 同一输入连续两次 rewrite：输出 **sha256 完全一致**（并行路径顺序确定）；
- 输出通过 `be-bem validate`（读取器与运行时同一套校验）；
- 优化后输出与第 3 轮输出哈希一致（26 MB 样本），说明只是变快、语义不变；
- 压缩级变化为 zstd 无损参数，只影响存储体积，不改变解码后的 payload。

## 4. 画质/兼容性

- 设备支持的纹理原样保留（零解码、零重编码）；
- 不支持的纹理按原有 ASTC/RGBA32 路径转换（法线语义保持 `xyz-unorm`）；
- 混合格式输出由 BEM reader / 运行时按每纹理 `format` 上传，兼容路径不变。

## 5. 未做/说明

- 端到端设备耗时未作为门槛（用户豁免）；设备侧可后续用 `stage=` 日志复核；
- “输入源 + 输出成品”两次写是格式转换的固有成本，已消除的是额外的 staging/临时副本；
- 转码结果缓存、几何 payload 与纹理阶段的流水线重叠列为后续可选优化。

## 6. 结论

在可复现的宿主基准上，核心 rewrite 路径已从 1270/2559 ms 降到 466/1306 ms（-62% / -49%），
确定性、校验、内存预算与画质兼容均满足既定目标；**目标达成（设备实测按用户要求豁免）**。
